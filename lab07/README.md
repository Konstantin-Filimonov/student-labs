# Лабораторная работа №7

## Тема
Эмбеддинги и семантический поиск: векторные представления текста, сходство и поиск по смыслу.

## Цель
Освоить построение воспроизводимого контура семантического поиска: подготовка корпуса → получение эмбеддингов → вычисление косинусного сходства → выдача top-k → оценка качества и производительности.

## Задачи
1. Подготовить корпус коротких документов по информационной безопасности.
2. Получить векторные представления документов и запросов с помощью локальной модели эмбеддингов.
3. Реализовать семантический поиск top-k по косинусному сходству.
4. Реализовать базовую линию (TF-IDF) для сравнения.
5. Рассчитать Precision@k, Recall@k, MRR и задержку.
6. Провести эксперимент с размером фрагмента на длинных документах.
7. Проанализировать риски информационной безопасности при хранении эмбеддингов.

## Используемые технологии
- Python 3.14
- sentence-transformers 5.x
- numpy, pandas, scikit-learn, pyyaml
- Модель эмбеддингов: `paraphrase-multilingual-MiniLM-L12-v2` (384 dim, CPU)
- ОС: Windows 11, CPU Intel Core i5-10300H

## Описание решения

### Этап 1. Подготовка корпуса
Основной корпус — **40 коротких синтетических документов** (1–2 предложения каждый) по темам: учётные записи, пароли, доступ, резервное копирование, инциденты, SOC, безопасная разработка, фишинг, политики, уязвимости, обучение, журналирование. Каждый документ имеет метаданные: `id`, `category`, `source`.

Дополнительно подготовлены **5 длинных документов** (2000–2500 символов) — фрагменты регламентов, чтобы эксперимент с размером чанка дал осмысленный результат. Реальные персональные данные и секреты не использовались.

### Этап 2. Получение эмбеддингов
Использована модель **`paraphrase-multilingual-MiniLM-L12-v2`** — многоязычная, работает на CPU, размерность 384. Эмбеддинги нормализованы (`normalize_embeddings=True`), поэтому косинусное сходство сводится к скалярному произведению.

Почему выбрана именно эта модель:
- поддерживает русский язык «из коробки», без дополнительного fine-tuning;
- компактная (~470 МБ), помещается на CPU и запускается без GPU;
- быстрая: 40 чанков кодируются за < 0.5 с.

### Этап 3. Поиск
Запрос кодируется той же моделью, вычисляется скалярное произведение со всеми векторами документов, выполняется сортировка по убыванию. Корректно, потому что векторы нормализованы.

### Этап 4. Базовая линия
Для сравнения реализован TF-IDF-поиск (`TfidfVectorizer` + косинусное сходство). Он не использует семантику, работает только с точными совпадениями слов и их форм.

### Этап 5. Оценка качества
Для **12 контрольных запросов** вручную определён эталон релевантности (1–3 документа). 7 из 12 запросов сформулированы разговорным языком или с использованием синонимов, чтобы показать преимущество семантического поиска над ключевым.

## Результаты

### Сводная таблица метрик (k=5, 12 запросов)

| Метод | Precision@5 | Recall@5 | MRR | Средняя задержка, мс |
|---|---|---|---|---|
| TF-IDF (ключевой) | 0.217 | 0.625 | 0.625 | **1.43** |
| Семантический поиск | **0.300** | **0.889** | **0.854** | 15.89 |

**Выводы по метрикам:**
- Семантический поиск даёт **+38% Precision@5** и **+42% Recall@5** относительно TF-IDF.
- MRR вырос с 0.625 до 0.854 — первый релевантный документ появляется в среднем на более высокой позиции.
- TF-IDF формально быстрее в 11 раз (1.43 мс против 15.89 мс), но разница в 14 мс несущественна для интерактивного поиска.

### Пример запроса
**Запрос:** «что делать если украли пароль» (нет слов «компрометация», «сеанс», «учётная запись»).

Семантический поиск корректно вернул в top-3 документы d26, d01, d27 — все они описывают действия при компрометации учётной записи. TF-IDF на этом запросе дал нерелевантные результаты, потому что в документах встречается только слово «пароль», но не сам смысл инцидента.

### Эксперимент с размером чанка

Проведён на 5 длинных документах (`data/long_corpus.jsonl`), 5 запросах с одним эталонным документом каждый, top-5.

| Размер чанка | Число чанков | Средняя Precision@5 |
|---|---|---|
| 300 | 31 | **0.20** |
| 800 | 15 | 0.16 |

**Интерпретация:**
- При размере чанка 300 все 5 запросов нашли релевантный документ в top-5 (0.20 = 5 × 1/5 / 5).
- При размере 800 — только 4 из 5 (0.16 = 4 × 1/5 / 5).
- Причина: крупный чанк (800 символов) объединяет несколько абзацев на разные темы и размывает семантический вектор. Мелкий чанк (300 символов) сохраняет фокус на одной подтеме, что улучшает ранжирование.
- Для данного корпуса оптимален размер **300 символов**. Однако это верно именно для этих документов: регламенты написаны короткими абзацами, каждый абзац — законченная мысль. Для другого корпуса оптимум может быть иным.

## Анализ информационной безопасности

- В корпусе нет реальных паролей, токенов, персональных данных, IP вне документационных диапазонов.
- **Эмбеддинги не являются анонимизацией.** Вектор содержит информацию о смысле исходного текста: по нему можно восстановить тему документа, а при наличии большого объёма пар «текст–вектор» — частично и содержание. Поэтому эмбеддинги — это **производные данные**, требующие такого же контроля доступа, как исходные документы.
- Метаданные (`source`, `category`) хранятся вместе с векторами, что позволяет фильтровать результаты по правам доступа.
- Модель работает **локально**, тексты не покидают машину. При использовании внешней модели эмбеддингов это было бы отдельным риском.

**Ответ на контрольный вопрос об угрозах (п. 6.1 методички):**

Фильтрация прав доступа должна применяться **на обоих этапах**:
1. **До поиска** — из индекса исключаются документы, недоступные пользователю. Это защищает от того, что документ вообще попадёт в top-k.
2. **После поиска** — повторная проверка метаданных каждого возвращённого фрагмента. Защита от ошибок конфигурации и от получения фрагмента по побочному каналу.

**Риски утечки:**
- через **текст ответа** — прямая выдача фрагмента;
- через **метаданные** (`source`, `category`) — можно узнать о существовании документа;
- через **оценки сходства** — даже без текста высокий `score` по запросу, содержащему чувствительные слова, косвенно подтверждает наличие соответствующего документа в базе.

Вывод: перед выдачей top-k необходимо отсекать документы, к которым у пользователя нет прав. При использовании внешней модели эмбеддингов нужно дополнительно фиксировать, куда передаются тексты и какие данные сохраняет поставщик.

## Вывод

В ходе работы установлено, что **семантический поиск находит документы по смысловой близости** даже при отсутствии точных совпадений слов. На подготовленном корпусе он превзошёл TF-IDF по всем метрикам качества (Precision@5: 0.30 против 0.22; Recall@5: 0.89 против 0.63; MRR: 0.85 против 0.63), уступив только по скорости — но разница в 14 мс несущественна для интерактивного поиска.

Эксперимент с размером чанка подтвердил гипотезу: **мелкие чанки (300 символов) дают более высокую точность**, чем крупные (800 символов), потому что сохраняют фокус на одной подтеме и не смешивают несколько тем в одном векторе.

Ключевые наблюдения:
- Модель `paraphrase-multilingual-MiniLM-L12-v2` корректно работает с русским языком и разговорными формулировками.
- TF-IDF выигрывает только на запросах с точным совпадением слов и техническими терминами.
- Для повышения качества в продуктивной системе имеет смысл рассмотреть **гибридный поиск** (объединение результатов семантического и ключевого поиска через reciprocal rank fusion).
- Результат этой работы является основой для следующей лабораторной по RAG: retrieval-компонент должен возвращать релевантные фрагменты с сохранением метаданных об источнике и правах доступа.

## Ограничения
- Корпус синтетический, 40 коротких + 5 длинных документов. Недостаточно для статистически устойчивых выводов.
- Оценка релевантности выполнена одним экспертом.
- Каждый запрос выполнен один раз; повторные измерения не проводились.
- Эксперимент с ANN-индексом (FAISS/Qdrant) не проводился: 40–71 вектор — слишком малый объём, чтобы приближённый поиск дал выигрыш.
