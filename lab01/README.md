# Лабораторная работа №1

## Тема

Тестирование локальной языковой модели через LM Studio: проверка
подключения, прогон набора промптов, замер задержки ответа и оценка
стабильности генерации.

## Цель

Изучить, как локально запущенная LLM (через LM Studio, OpenAI-совместимый
API) отвечает на разные типы запросов, насколько стабильны её ответы при
повторных вызовах и как измерить время отклика.

> Заполните своими словами, если формулировка цели преподавателем отличалась.

## Задачи

1. Настроить подключение к локальному серверу LM Studio через
   OpenAI-совместимый клиент.
2. Проверить, что модель, указанная в конфигурации, действительно доступна
   на сервере.
3. Прогнать набор тестовых промптов разных типов и зафиксировать ответы и
   задержку каждого запроса.
4. Оценить стабильность ответов модели (повторные запросы с одинаковым
   промптом).
5. Подготовить шаблон для ручной оценки качества ответов и свести результаты
   в единый отчёт.

## Используемые технологии

- Python 3.x
- библиотека `openai` (OpenAI-совместимый клиент)
- `python-dotenv` для чтения `.env`
- LM Studio — локальный сервер, отдающий модель по OpenAI-совместимому API
  (`http://localhost:1234/v1`)

Модель: указывается через переменную окружения `LLM_MODEL` (берётся из
`.env`, конкретное имя — то, что реально загружено в LM Studio).
Запуск: локальный, через LM Studio.
Температура и другие параметры генерации в этой работе не переопределялись
(используются значения по умолчанию) — их исследование вынесено в ЛР2.

## Описание решения

### Этап 1. Подключение к модели

Для работы с локальной моделью выбран LM Studio, поскольку он поднимает
OpenAI-совместимый REST API поверх локально загруженной модели — это
позволяет использовать стандартный клиент `openai` без переписывания кода
под отдельный формат API. Адрес сервера и имя модели вынесены в `.env`
(`LLM_BASE_URL`, `LLM_MODEL`), чтобы не хардкодить их в коде и иметь
возможность быстро переключаться между моделями.

`main.py` перед отправкой запроса дополнительно запрашивает у сервера
список реально загруженных моделей (`list_available_models`) и сверяет его
с именем модели из `.env` — это защищает от типичной ошибки, когда в
конфиге указано одно имя модели, а в LM Studio загружена другая.

### Этап 2. Прогон набора промптов

Промпты вынесены в отдельный файл `prompts.py` и размечены по типу
(`prompt_type`), чтобы результаты можно было анализировать не только по
отдельным ответам, но и по категориям запросов. `run_experiment.py`
последовательно отправляет каждый промпт, ловит исключения по каждому
запросу отдельно (а не прерывает весь прогон при одной ошибке) и
дозаписывает результат в `results/experiment_results.csv` — это позволяет
перезапускать эксперимент по частям и накапливать историю прогонов.

### Этап 3. Оценка стабильности

`bonus_stability.py` повторяет один и тот же промпт несколько раз, чтобы
увидеть, насколько сильно варьируются ответы модели при одинаковых входных
данных и параметрах по умолчанию.

> Опишите здесь своими словами: какой именно промпт повторяли, сколько раз,
> и что заметили — ответы были почти одинаковыми или сильно расходились.

### Этап 4. Сведение результатов

`summarize.py` агрегирует `experiment_results.csv` (например, среднюю
задержку, число ошибок), а `make_scoring_template.py` готовит таблицу для
ручной оценки качества ответов, поскольку автоматически объективно оценить
"хорошесть" свободного текста сложно — для этого нужна разметка человеком.

## Запуск

Установить зависимости:

```bash
pip install -r requirements.txt
```

Создать `.env` на основе примера и указать реальные значения:

```bash
cp .env.example .env
```

Запустить LM Studio, загрузить нужную модель и включить локальный сервер
(обычно на порту `1234`). Проверить, что нужная модель реально загружена:

```bash
curl http://localhost:1234/v1/models
```

Проверить подключение и получить один тестовый ответ:

```bash
python src/main.py
```

Прогнать полный набор промптов из эксперимента:

```bash
python src/run_experiment.py
```

Проверить стабильность ответов:

```bash
python src/bonus_stability.py
```

Свести результаты и получить шаблон для оценки:

```bash
python src/summarize.py
python src/make_scoring_template.py
```

### Переменные окружения

```text
LLM_API_KEY       # для LM Studio можно оставить значение по умолчанию "lm-studio"
LLM_BASE_URL      # адрес локального сервера, по умолчанию http://localhost:1234/v1
LLM_MODEL         # точное имя модели, загруженной в LM Studio
LLM_MODEL_LABEL   # произвольная подпись модели для отчётов (необязательно)
```
