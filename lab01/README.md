# Лабораторная работа №1

## Тема

Подключение к локальной языковой модели через LM Studio и сравнение качества ответов на типовых задачах информационной безопасности.

## Цель

Понять, как локальная LLM ведёт себя на разных типах запросов: объяснение понятий, классификация событий, извлечение данных, генерация кода, жёсткий формат. Зафиксировать задержку и сравнить две модели на одном наборе промптов.

## Задачи

1. Поднять OpenAI-совместимый клиент к LM Studio.
2. Проверить, что имя модели из `.env` совпадает с тем, что отдаёт сервер.
3. Прогнать 10 промптов разных типов и сохранить ответы с задержкой.
4. Сравнить `google/gemma-4-e4b` и `deepseek-r1-distill-qwen-1.5b` на одном наборе.
5. Подготовить CSV-шаблон для ручной оценки ответов.

## Используемые технологии

- Python 3
- `openai`, `python-dotenv`, `pandas`
- LM Studio, локальный API `http://localhost:1234/v1`

Модели (локальные, через LM Studio):

| Подпись в CSV | Идентификатор на сервере |
|---|---|
| Model A | `google/gemma-4-e4b` |
| Model A | `deepseek-r1-distill-qwen-1.5b` |

В обоих прогонах `LLM_MODEL_LABEL` остался `Model A`, поэтому модели в таблице различаются по полю `model_name`, а не по подписи. Параметры генерации в этой работе не задавались явно — влияние temperature и max_tokens исследуется в [лабораторной №2](../lab02/).

## Описание решения

### Этап 1. Подключение

Выбран LM Studio, потому что он даёт тот же протокол, что и OpenAI Chat Completions. Код не привязан к облачному провайдеру: достаточно сменить `LLM_BASE_URL` и `LLM_MODEL`. Ключ API для LM Studio не проверяется, но клиент `openai` требует непустую строку, поэтому в `.env.example` стоит `lm-studio`.

`main.py` сначала запрашивает `GET /v1/models` и сравнивает список с `LLM_MODEL`. Это ловит типичную ошибку: в конфиге одно имя, а в LM Studio загружена другая модель.

### Этап 2. Набор промптов

Промпты вынесены в `prompts.py` и размечены типом задачи. Так можно смотреть не только отдельные ответы, но и то, где модель ломает формат (классификация «только слова через запятую», JSON без текста вокруг). `run_experiment.py` ловит ошибку на каждом запросе отдельно и дописывает CSV, чтобы один сбой не обнулял весь прогон.

### Этап 3. Сравнение моделей

Один и тот же список из 10 запросов прогнан на Gemma и на Distill-Qwen. Это честнее, чем судить о «локальной LLM вообще» по одной модели: различия по скорости и следованию инструкции оказались больше, чем различия между типами промптов внутри одной модели.

### Этап 4. Шаблон оценки

Автоматически оценить свободный текст по корректности нельзя без эталона. `make_scoring_template.py` копирует ответы в таблицу с колонками 0–2. Файл `results/scoring_template.csv` — заготовка; выводы ниже опираются на ручной разбор ответов из `experiment_results.csv`.

## Запуск

```bash
cd lab01
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

В LM Studio загрузить модель, включить Local Server, вписать точное имя в `LLM_MODEL` (его можно взять из `curl http://localhost:1234/v1/models`).

```bash
python src/main.py
python src/run_experiment.py
python src/make_scoring_template.py
```

Переменные окружения: `LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`, `LLM_MODEL_LABEL`.

## Результаты

Полные ответы: [results/experiment_results.csv](./results/experiment_results.csv).

Средняя задержка на 10 запросов:

| Модель | Средняя задержка | Мин. | Макс. |
|---|---:|---:|---:|
| `google/gemma-4-e4b` | 122.5 с | 4.1 с | 285.1 с |
| `deepseek-r1-distill-qwen-1.5b` | 8.8 с | 4.0 с | 15.3 с |

Gemma на объясняющих промптах уходит в длинные эссе (хеш-функция — 285 с). Distill-Qwen отвечает быстрее, но хуже держит формат.

Пример запроса из `main.py`: объяснить разницу между хешированием и шифрованием. Gemma даёт развёрнутый ответ с аналогиями; Distill-Qwen — короче и чаще смешивает английский с русским.

Жёсткий формат (промпт 10, JSON про Python):

- Gemma вернула JSON со схемой `language` / `paradigm` / `year_created`.
- Distill-Qwen обернула JSON текстом «Here is your exact and precise answer…» и оставила пустой `paradigm`.

Классификация четырёх сетевых событий (промпт 2, «только слова через запятую»):

- Gemma почти уложилась в формат, но допустила опечатку: `нормальное,дозрительное,нормальное,подозрительное`.
- Distill-Qwen проигнорировала ограничение и написала разбор абзацами на английском.

Извлечение ФИО/должности/даты (промпт 4):

- Gemma: `name` = Иванов Пётр Сергеевич, `position` = системный администратор.
- Distill-Qwen разрезала ФИО: `name` = Иванов, `position` = Пётр Сергеевич.

## Вывод

Локальная модель через LM Studio работает как обычный OpenAI-клиент, но имя модели нужно сверять со списком `/v1/models`. На CPU/слабом ускорителе задержка Gemma на «объясняющих» запросах измеряется минутами — для серии экспериментов это уже ограничение методики, а не только UX.

Качество нельзя сводить к скорости: быстрая Distill-Qwen чаще нарушает инструкцию и путает поля JSON. Для задач ИБ, где нужен машиночитаемый ответ, важнее явный формат в промпте и проверка схемы, чем «просто спросить модель». Сравнение двух моделей на одном наборе показало это надёжнее, чем один прогон.
