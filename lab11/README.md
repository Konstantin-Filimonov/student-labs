# Лабораторная работа №11

## Тема
Разработка ИИ-агента и агентного цикла (Agent Loop): планирование действий, инструменты, наблюдения, контроль остановки и информационная безопасность.

## Цель
Создать на Python учебного агента-помощника аналитика SOC, который по заданию последовательно выбирает инструменты, анализирует наблюдения, завершает работу при достижении цели либо при срабатывании ограничений и не выходит за выданные полномочия (только чтение, вымышленные данные).

## Сценарий
По идентификатору инцидента агент читает запись (`get_incident`), проверяет условную репутацию IP-адреса **из этой записи** (`lookup_ip`), находит инструкцию реагирования (`search_knowledge`) и готовит краткое заключение. Следующий шаг зависит от результата предыдущего: IP становится известен только после чтения инцидента — поэтому нужен цикл, а не одиночный вызов (ЛР10). Вариант 1 (SOC); все записи и IP вымышлены (диапазоны RFC 5737).

## Архитектура
```text
цель ─► [LLM] ─► tool_calls? ─нет─► completed (окончательный ответ)
          ▲          │да
          │          ▼
          │   Политика приложения (вне LLM):
          │   лимиты (раунды / вызовы / время) → повтор? → allowlist → роль → JSON → поля/тип → значение
          │          │
          │          ▼
          │   инструмент (только чтение) ─► наблюдение O_t
          └── role=tool + tool_call_id ◄────┘   (история сохраняется целиком)
```
Агент — вся прикладная система, а не модель: модель только *предлагает* действие, решение и выполнение — на стороне приложения.

## Запуск (Windows PowerShell; Python 3.10+)
```powershell
cd lab11
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
copy .env.example .env

python src/agent11_demo.py --self-test          # ожидается: SELF-TEST: OK
python src/agent11_demo.py --demo               # ожидается: completed, rounds=4, calls=3
python -m unittest discover -s tests -v         # 40 тестов, без модели
```
`--self-test`, `--demo` и тесты работают на стандартной библиотеке (пакет `openai` не нужен).

### Реальная модель (LM Studio)
1. В LM Studio загрузить `qwen2.5-3b-instruct` (или другую модель с поддержкой tool use), вкладка **Developer → Start Server** (порт 1234).
2. В `.env` проверить `LM_STUDIO_MODEL` — точное имя модели из LM Studio.
3. Проверить поддержку инструментов: `python src/check_model.py` (должно быть «Tool calling поддерживается»).
4. Один запуск: `python src/agent11_demo.py`
   или с параметрами: `python src/agent11_demo.py --task "Проанализируй инцидент INC-102 ..." --max-rounds 4 --trace-file experiments/last_trace.jsonl`
5. Серия экспериментов (10 задач × 3 повтора × max_rounds = 2 и 6):
   ```powershell
   python src/run_experiments.py --mode real --rounds 2 6 --repeats 3
   python src/plots.py
   ```
   Строки `real_*` добавляются в `experiments/metrics.csv` рядом с `sim_*`; ответы модели вручную не правятся.
6. Необязательно (этап 6): RAG из ЛР9 — `KB_BACKEND=lab09` в `.env` (код ЛР9 ищется в `../lab09/src`; при недоступности — честное переключение на keyword с сообщением в stderr).

## Инструменты и коды результата
| Инструмент | Параметр | Назначение |
|-|-|-|
| `get_incident` | `incident_id` (`INC-101`) | запись инцидента |
| `lookup_ip` | `ip` | условная оценка риска IP |
| `search_knowledge` | `query` | инструкции SOC; возвращает `id` источника и текст |

`dispatch` всегда возвращает словарь: `data` или `error` ∈ {`forbidden_tool`, `permission_denied`, `invalid_json`, `invalid_arguments`, `invalid_id`, `invalid_ip`, `invalid_query`, `not_found`, `internal_error`}; в цикле добавляются `repeated_call` и `tool_budget_exceeded`. Ошибка инструмента — это наблюдение для модели, а не исключение всего процесса.

## Остановка цикла
| Статус | Условие |
|-|-|
| `completed` | ответ модели без новых `tool_calls` |
| `round_limit` | исчерпан `max_rounds` (по умолчанию 6) |
| `tool_budget_exceeded` | вызов сверх `max_calls` (по умолчанию 8) |
| `time_limit` | превышен `max_seconds` (по умолчанию 75); на запрос к API — тайм-аут 20 с |
| `api_error` | ошибка модели (сохраняется только тип исключения) |

Дополнительно: повторный вызов с теми же аргументами (с учётом пробелов и порядка ключей) не исполняется — `repeated_call`; на **каждый** `tool_call_id` всегда возвращается сообщение `role=tool`, даже при отказе.

## Метрики и эксперименты
Набор из 10 задач (`data/scenarios.jsonl`). Успех (TSR) требует одновременно: статус `completed`, нужные шаги в трассе, корректные аргументы цепочки, отсутствие лишних вызовов, ожидаемые факты в ответе, отсутствие «канарейки» из недоверенного документа, ссылку на источник (где нужна). Красивый текст без инструментальных шагов успехом не считается.

**Имитатор (`mode=sim`) проверяет управляющую логику, а не качество модели.** Это детерминированная программа, а не LLM; её 100 % при `max_rounds=6` показывают лишь, что цикл, лимиты и политика работают.

| Режим | Задач × повторов | TSR, % | Вызовов на задачу | Среднее время, с | Ошибки/лимиты, % |
|-|-|-|-|-|-|
| Имитация, 2 раунда | 10 × 1 | 60,0 | 1,3 | <0,01 | 40,0 |
| Имитация, 6 раундов | 10 × 1 | 100,0 | 1,9 | <0,01 | 0,0 |
| Реальная LLM, 2 раунда | 10 × 3 | *будет заполнено после запуска* | | | |
| Реальная LLM, 6 раундов | 10 × 3 | *будет заполнено после запуска* | | | |

Полная таблица — `experiments/metrics.csv`; графики — `experiments/plots/tsr_by_rounds.png`, `latency_calls.png`; трассы без секретов — `experiments/traces_sanitized.jsonl`; конфигурация запуска — `experiments/run_meta.json`.
Safety Block Rate: 11 из 11 синтетических опасных вызовов заблокированы политикой без участия модели (`safety_probe.csv`).

## Информационная безопасность
| Угроза | Защита |
|-|-|
| Prompt injection во внешних данных | документ и вывод инструмента приходят только как `role=tool`; решение о вызове принимает политика вне LLM (T10) |
| Избыточные полномочия | только чтение; нет shell, записи, удаления, произвольных URL; права по ролям задаёт приложение |
| Неверный инструмент / аргументы | allowlist, точный набор полей, типы, формат значений; функции вызываются только через `REGISTRY` |
| Бесконечные вызовы, перерасход | `max_rounds`, `max_calls`, `max_seconds`, тайм-аут API, детекция повторов |
| Утечка секретов и ПДн | ключи только в `.env` (в `.gitignore`), данные вымышлены, трасса очищается и усекается, текст исключений API не сохраняется |
| Ложные выводы | выводы сверяются с трассой; в промпте требование указывать источник и неопределённость |

Отказ в опасном вызове — гарантия политики приложения, а не устойчивости самой модели к инъекциям: модель может «поддаться» и написать лишнее в ответе, поэтому «канарейка» в ответе учитывается в TSR отдельно.

## Ограничения
- Данные учебные и крошечные; keyword-поиск не семантический.
- Результаты малой локальной модели (3B) зависят от версии, квантования и параметров; на одном запуске выводов об «эффективности модели» не делать. Если модель не возвращает `tool_calls`, это фиксируется как ограничение, а не исправляется вручную.
- Итоговый ответ — не экспертное заключение; в реальном режиме его необходимо сверять с трассой.
- Бэкенд `lab09` подключается к коду ЛР9 как есть и требует его зависимостей (sentence-transformers и др.).
